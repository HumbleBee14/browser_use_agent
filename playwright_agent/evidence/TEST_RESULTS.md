## Known Behavior: Repeated Actions (Screenshot Spam)

**What happens:** The agent sometimes takes 2-3 screenshots of the same page before extracting data and calling done. This varies between runs — same input can produce 1 screenshot or 3.

**Why:** Claude's reasoning is non-deterministic. Each step, it independently decides the "single best next action." Sometimes it takes an extra screenshot because it's not confident it captured enough, or the page state changed slightly between steps (dynamic sites like LinkedIn/GitHub). It's not a bug in the engine — it's LLM reasoning variance.

**How we handle it:** The engine has a **consecutive-action detector** — if the same action is called 3 times in a row, a hard nudge is injected: *"STOP repeating this action. Extract the fields and call done now."* Any different action in between (scroll, click, extract) resets the counter. This caps the worst case to 3 redundant actions before the agent is forced to proceed.

**Impact:** Minimal. Extra screenshots cost ~1-2 seconds each and waste disk space, but the extracted data is always correct. The evidence is still valid — extra screenshots just show the same page state.

## How to Verify Any Result

```bash
# 1. Check combined CSV
cat evidence/run_XXXX/combined.csv

# 2. Check per-sample extracted data
python -c "import json; d=json.load(open('evidence/run_XXXX/sample_id/result.json')); print(json.dumps(d['extracted'], indent=2))"

# 3. Check agent trace (what it did step by step)
python -c "import json; [print(f'Step {s[\"step\"]}: {s[\"action\"]} → {s[\"result\"][:80]}') for s in json.load(open('evidence/run_XXXX/sample_id/action_log.json'))]"

# 4. Verify screenshot integrity (SHA-256)
python -c "
import hashlib, json
r = json.load(open('evidence/run_XXXX/sample_id/result.json'))
for a in r['artifacts']:
    actual = hashlib.sha256(open(f'evidence/run_XXXX/sample_id/{a[\"filename\"]}','rb').read()).hexdigest()
    print(f'{a[\"filename\"]}: {\"MATCH\" if actual == a[\"sha256\"] else \"MISMATCH\"}')
"
```
